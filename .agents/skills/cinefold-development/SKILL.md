# cinefold 功能开发

先读根目录 `AGENTS.md`，沿用用户最新选择。此技能不授权部署、推送、发送通知或启动线上清理任务。

## 从用户操作到最终结果

动手前沿现有代码跟踪实际调用链：页面入口 → 请求字段 → API 校验 → 服务 → 数据库/文件/外部系统 → 状态查询 → 页面结果。记录本次要改变的行为与会受影响的旧入口；不要凭按钮名称判断功能已存在。

为本次改动列出简短的验收场景，优先覆盖跨层的真实风险：

- 页面刷新或重新打开后，选择、计数和按钮状态是否与服务端一致。
- 后台任务排队、执行、部分失败、中断和完成，是否均有明确结果；重复点击是否重复执行。
- 任务中断时，哪些数据已提交，哪些文件已移动，哪些结果可重用。仅保存进度不等于支持断点继续。
- 新增参数是否贯穿所有入口、后台线程和恢复记录；默认行为是否兼容旧数据。

小改动只检查相关路径，不为文案或布局调整强加数据库迁移、复杂测试或审批流程。

## 功能变更同步助手

用户要求：新增或修正功能时，同步更新 cinefold 内置 AI 助手，不能只修改网页和服务，让助手继续使用旧能力或旧说法。将助手作为功能调用链的一部分核对。

- 新增查询、来源、榜单、筛选条件或任务能力时，检查 `app/modules/agent/tools.py` 的实现、REGISTRY 和 TOOL_SCHEMAS，复用业务服务，保持参数、范围、返回状态和页面一致；不另写一套简化业务逻辑。
- 功能修复、更名、移动或移除时，同步修改 `app/modules/agent/agent.py` 的能力说明、工具描述和返回文案，去除过期入口与配置，避免助手承诺尚未实现的能力。
- 可改变订阅、下载、任务、配置或文件的助手入口沿用 `actions.py` 的待确认提案和实际执行链，前端确认展示真实目标及结果；不能仅凭模型回复宣称执行成功。沿用会话内既有授权，技能本身不新增外部操作权限。
- 助手前端、消息渠道或 MCP 暴露同一能力时，核对各入口的参数与结果映射；新增只读查询不应触发订阅或下载。覆盖本次受影响的工具调用和实际业务结果，不能只检查 schema 中存在工具名。

对于纯样式或不改变助手可见行为的内部调整，核对现有映射仍准确即可，不添加无意义的工具或提示词改动。交付时简要说明助手已同步的能力与尚未提供的入口。

调度注册表与实际已排期任务不是同一个集合：cron 留空的任务仍须出现在任务页与助手 list_tasks 中，允许手动执行，不能只遍历 APScheduler.get_jobs() 而把入口藏掉。新增榜单共用 `modules/ladysite/ranks.py` 的身份，读取、缓存、订阅与助手参数必须使用同一 key；FC2 不能用无码或有码结果冒充。旧项目的签名 API 必须直连代理并关闭 bypass，否则自定义签名头会丢失；接入测试通过不等于线上旧 API 仍可用。

助手聊天记录在 `modules/agent/history.py` 按账号及每轮独立保存到数据库，分页读取，不将整段历史放进常驻字典。autoflush=False 时先 flush 再取得新记录 ID；清空后迟到的回答不得重建已删除记录。恢复历史提案时核对内存中真实有效的提案，已执行、取消、替换与过期状态不能恢复成待执行。实际操作成功后，历史状态保存失败不得把接口变成“操作失败”并诱导再次执行；区分业务操作结果和聊天记录保存结果。聊天 namespace 不参与通用缓存过期清理，验证账号隔离、分页、重启中断和清空。

## 本项目不能混淆的对象

- 下载源视频、播放目录中的硬链接、可再生的 NFO/封面、字幕及数据库收藏/观看记录具有不同生命周期。
- NFO/图片改写、缺失或生成失败不能阻断整批重建；保留单文件错误供汇总。源视频身份异常、路径越界和符号链接仍需明确处理。
- 继续任务必须读取原任务的检查点和结果，跳过已完成影片；不得再次清空已重建的文件。重试失败项不得扩大为全库重刮。
- 多分集按基础影片分组处理；带字幕/破解等版本后缀不能作为新的网络番号查询。不要把相同番号直接当成相同文件。
- Emby 合集/收藏操作与本地影片文件分开处理；不得因同步或重试而重复创建合集或触发源文件删除。

## 状态和落盘

长任务使用后台执行；界面显示当前阶段、该阶段的计数/字节、当前文件或番号、耗时和最后进度更新时间。未知总量显示处理中，不编造百分比。

恢复信息记录原任务标识、输出目录、执行选项、检查点、源文件身份、已提交结果和失败原因。影片完成结果在推进计数前持久化。考虑旧版本恢复文件和最后一行未完整写入的日志；损坏的中间记录不能被当成成功。

数据库检查以真正的生产配置验证：当前生产会话 `autoflush=False`，生产数据库为 PostgreSQL；SQLite 测试通过不能代替 PostgreSQL 行为验证。新增数据表需接入模型注册，避免已有数据或用户状态被覆盖。

图片维护的扫描→聚合→状态保存→预览完成必须在 PostgreSQL 临时表中整链验证；只单测 upsert 会漏掉聚合类型差异。PostgreSQL `SUM(bigint)` 经 psycopg 返回 `Decimal`，写入 JSON 检查点前将容量与计数归一为整数，并覆盖空目录。聚合写入失败后若错误状态还携带同一非法值，错误保存也会再次失败，留下 running 记录而线程已退出，界面就可能误判重启。扫描中逐批持久化已扫描字节，未知总量显示待统计；后台线程不在只能说明任务中断，不能据此断言服务重启。

定位入口可从以下文件开始，继续以当前代码为准：

- 重建：`app/services/scraperebuild.py`、`app/api/endpoints/scrape.py`。
- 手动任务与清单：`app/services/scrapesources.py`、`app/services/scrapeinventory.py`。
- 刮削产物与查重：`app/services/scrape.py`、`app/services/mediaduplicate.py`。
- 页面：`web/src/components/DownloadSources.vue`，进度组件和 `web/src/utils/rebuild.js`。

## 验证与交付

容器内存排查先拆分主进程、子进程 RSS 与 cgroup 文件缓存，不能把 Docker 总量都归因于 Python 或代理，也不能仅凭空闲时 RSS 高就认定泄漏。Transmission `get_torrents()` 未指定字段会拉取完整种子资料；文件扫描应按 hash 分批，只取 `downloadDir/files` 并逐条消费原始 `torrent.fields['files']`。`get_files()` 另依赖 `priorities/wanted`，只需路径时不要构造 File 对象。孤儿检查只保留本轮源路径的精确匹配，概率过滤器不能代替文件归属核验。优化需在独立进程测峰值，并核对全路径多重集及匹配结果一致；不得把诊断进程的改善写成线上主进程已经下降。

热更新仅重启 Python 时，容器 ID 与 cgroup 缓存可能沿用；对比内存要同时记录容器启动时间、Python 进程年龄和至少一轮实际任务后的 RSS，不能把刚启动的进程与旧进程直接当成长期对照。cgroup v1 的 Docker CLI 只减去 `total_inactive_file`，活跃文件缓存仍计入面板值，见 [Docker stats 说明](https://docs.docker.com/reference/cli/docker/container/stats/)。容器内另起诊断 Python 时，须先调用 `app.core.overlay.activate()` 再导入业务模块，否则可能读取镜像旧代码，出现线上已有新版本但诊断导入新模型失败的假象。

周期扫描的图片校验不得调用 `jpeg_bytes()` 重新编码来取得布尔值；`Image.open()` 本身只懒加载头部，仍需完整 `load()` 才能拒绝截断图片，见 [Pillow 图片读取](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.open)。`scrapewatch._complete()` 的持久化校验在 `services/artifactvalidation.py`，以路径及设备/inode/大小/mtime_ns/ctime_ns 识别未变文件，DB 与有界 LRU 只复用成功校验，不持有图片内容。临时读取失败不能永久缓存为损坏；换算法时更新缓存 namespace 版本。可在 PostgreSQL 临时表中清空 LRU 后禁止打开图片，验证“重启”仍从 DB 命中，并单独检验替换同大小、同 mtime 文件能触发重新解码。

下载器文件索引的入口在 `app/services/downloadindex.py`：按连接身份隔离缓存，只用完整成功的列表标记种子已移除。文件快照和完成标记须同事务提交，失败保留旧版本并降频重试；后台同步按尚未更新的条目轮换。删除确认后写墓碑，以观测时间阻止先开始、后返回的旧快照将记录恢复为存在。转移目标接管与源任务删除是两个独立事实，失败不能提前改源状态。普通身份反查可复用近期数据库索引，真正删除前仍走实时归属核验；不要把数据库里整张索引表重新加载进全局 Python 字典。

网页图片缓存与媒体目录产物分别管理。缓存改格式时同时验证响应字节、MIME、ETag、旧 `local_banner` 地址回退以及淘汰后的回源；不能只改落盘字节而继续响应旧内容。`kind=still` 必须包含来源 URL 的身份，否则同一番号的不同剧照会共用缓存文件。持久化维护检查点记录目录、策略和游标；重启后继续要跳过已提交文件，删除前重新确认文件身份、最近访问和重要影片保护。只清理可确认回源的网页缓存，不顺带清理 `extrafanart` 或源视频。

目录增量不能只看根目录 mtime；字幕索引保存每个子目录的身份和子目录名单，未变化时复用 DB，周期全量对账。根目录不可用或子树读取失败时保留旧索引。源视频复用至少核对设备/inode/大小/mtime_ns/ctime_ns，不能把同大小、同 mtime 的替换文件当成原文件；全量核验时间与轻量扫描时间分开保存，否则频繁扫描会让全量核验永不触发。

后台资源预算要允许同线程嵌套，重任务等候时保持 queued，播放轮询使用独立调度执行器，避免所有调度线程被等待预算的扫描占满。文件锁和图片编码限流锁保持统一的获取顺序，避免维护线程与缩略图请求互相等待。复用下载器完整快照时传递 RPC 开始观测时间，不能用返回时间替代，否则旧快照可能越过删除墓碑；部分刷新不用于推断任务消失。任务前后 RSS 是全进程样本，包含同时运行的其他工作，不能归因为单任务独占内存。

原生资源爬虫入口在 `services/resourcecrawler.py`，资源与失败冷却分别存入 `ResourcePost`、`CrawlerAttempt`。成功资源、未订阅番号占位和待处理队列检查点同事务提交；先构造下一份状态，提交成功后再更新内存状态，否则提交失败会跳过未落库帖子。用 PostgreSQL 临时表在提交前中断并继续，不能只测正常 upsert。失败补抓需限制份额，给新帖留额度；合集中存在多个明确番号时不自动匹配，帖子标题不写成影片元数据。本地资源在远程搜索缓存外合并，沿用 BT 自动下载开关。旧 article 数据库导入已移除，不重新引入迁移入口或外部库依赖。

论坛图片地址已入库不等于浏览器能直接显示：图床实测无 Referer 返回 403，带论坛 Referer 返回 200。资源卡片通过 `resourceimages.py` 按已保存的资源 key 和图片索引鉴权转发，逐次验证重定向到公网地址，限制响应体和并发，不落盘缓存；不要为论坛图片放开任意 URL 代理。封面懒加载、图库展开才挂载其余图片，统一使用 PrivateImage 验证隐私模式。磁链推送复用 download_torrent 的历史与状态更新；显式选择 QB 时先核对已配置客户端，禁止静默回退到 TR，保留重复下载确认。

色花堂 HTTP 200 且标题为 SEHUATANG.ORG 可能仍是年龄确认页：实测同一出口返回 safeid，带 `_safe` Cookie 再请求即可进入列表。确认请求用 ContextVar 临时固定已知 Mihomo 节点，结束后恢复节点轮换；发给兄弟容器 TRAWL 时将本机回环入口改为配置的 trawl_host。同步与预算异步路径均须返回 FetchedPage 并保留出口、Cookie、User-Agent，否则带总时限的抓取会丢会话身份。缺失列表可在原总时限内重试一次，但导航页、维护页和登录限制应分别识别，不当成 Cloudflare 无限重试。X1080X 发布页可能经相对链接和 meta refresh 指向新论坛地址，域名变化时不得携带旧域 Cookie。

论坛可能以 HTTP 200 返回 Cloudflare 验证页，需检查标题后复用既有 bypass。附件请求须配对页面得到的 Cookie、User-Agent 和代理出口；这些会话凭据只在内存使用，不进入爬虫状态 API。HTML 登录页和无效 torrent 不能当成无资源或用整段响应摘要冒充 info hash。正文体积只解析明确的 G/M/T 数值，不能把 `.torrent` 的 `.t` 或分辨率 `4K` 当成体积。

修改内置 Mihomo 路由时，保留固定代理端口与按认证身份分流：`IN-USER` 匹配稳定的节点身份，不用端口偏移识别节点，也不在并发请求间切换全局代理组。预检、租约、失败冷却和日志需使用同一身份解析；节点重排不应改变旧身份的出口，已替换节点的旧身份应失效。不要跳过回环地址的认证，否则本机请求无法按用户分流。

此链路需用真实内核验证并发 HTTP 与 HTTPS CONNECT 分流及认证拒绝，不能只断言生成的配置。构造 HTTP 上游测试桩时注意 Mihomo 会使用 CONNECT 建隧道；v1.19.33 实测错误认证返回 403、缺失认证返回 407，均不能转发至目标。Docker `EXPOSE` 范围修改后需更新镜像并重新创建容器，仅重启不会清除原容器端口声明。规则依据：[Mihomo IN-USER](https://wiki.metacubex.one/config/rules/#in-user)。

用相关回归测试验证成功路径和本次具体故障；恢复任务应在真实检查点中断后继续，验证完成项未重做、已生成文件未删除。不要只断言函数被调用。

网页交互按用户规则使用 Playwright MCP。可用本地页面配合模拟 API 验证按钮、首次打开、刷新、计数和明细展开；明确标注模拟环境，不将它写成线上重建已验证。没有工具时说明限制，不用 REA 替代。

运行适当的后端测试、前端状态测试和构建。报告哪些行为已验证、哪些尚未验证，以及代码是否提交、推送、部署。不能把修复在本地写成线上已恢复。Git 提交遵守根目录版本规则。
